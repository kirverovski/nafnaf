Папка **`тестовые лендинги/`** содержит **черновики лендингов, НЕ готовые к публикации**.

| Файл | Тема | Статус |
|---|---|---|

| `pennaya-vecherinka.html` | Пенная вечеринка | 🟡 черновик, на проработке у владельца |
| `soap-bubbles.html` | Шоу мыльных пузырей | 🟡 черновик, на проработке у владельца |

### Что это значит для ИИ и разработчика

1. **НЕ публиковать** эти страницы: не добавлять в меню, кнопки, тексты, sitemap.xml, футеры и любые другие видимые места основных страниц.
2. **НЕ удалять** эти файлы и **не переименовывать** папку — владелец дорабатывает их и вернёт к публикации позже.
3. **НЕ добавлять** ссылки на них из других файлов (кроме документов внутри самой папки).
4. **НЕ включать** эти страницы в sitemap.xml и **не снимать** запреты из robots.txt / meta-тегов noindex, пока владелец явно не попросит.
5. **НЕ переносить** файлы из этой папки в корень сайта без явной просьбы владельца.
6. Страницы внутри папки **уже помечены** `<meta name="robots" content="noindex, nofollow">` — сохраняй этот тег при редактировании.
7. Страницы в папке могут **устаревать** относительно основных (модалки, цены, стили). Считай их снапшотами: не синхронизируй автоматически, не «исправляй расхождения» без запроса.
8. Пути внутри черновиков переписаны с префиксом `../` (`../css/style.css`, `../index.html`, `data-images="../images/…"`), чтобы страницы открывались и предпросматривались прямо из папки. **Не «исправляй» эти префиксы** и помни: при переносе в корень их нужно убрать (см. шаг 2 ниже).

### Как вернуть лендинг в публикацию (когда владелец попросит)

1. Переместить файл из `тестовые лендинги/` в корень сайта.
2. Убрать префиксы `../` из всех `href`, `src`, `onclick="window.location.href='…'"` и `data-images`.
3. Убрать `<meta name="robots" content="noindex, nofollow">` из `<head>`.
4. Обновить `<link rel="canonical">` (путь в корне) и og:url.
5. Добавить страницу в `sitemap.xml`.
6. Добавить ссылки в меню (`<nav class="desktop-nav">`) основных страниц и при необходимости — в блоки «С чем часто заказывают».
7. Убрать запрет папки черновиков из robots.txt (строка `Disallow: /%D1%82…` в каждой группе `User-agent`) — только percent-encoding, кириллицу Яндекс.Вебмастер считает недопустимым символом.
8. Обновить этот файл (AI-CONTEXT.md): перенести страницу из таблицы «черновики» в «опубликованные».

## 🛠 Панель управления (admin.html)

Владелец правит услуги, цены и описания на сайте через **nafnafiki.ru/admin.html** —
без редактирования кода. Вход по паролю (хеш SHA-256 в `js/admin-ui.js`, сам пароль
в коде отсутствует) + Personal Access Token владельца (хранится только в
localStorage его устройства).

Как это работает:
1. Панель читает HTML-файлы разделов через GitHub Contents API и находит карточки
   по классам `card service-card` (парсер — `js/admin-core.js`).
2. Правка меняется **точечно**: в файл записывается только отредактированное
   значение, остальной HTML остаётся байт-в-байт прежним (не съезжают SEO-блоки,
   микроразметка, метрика).
3. «Сохранить» создаёт коммит в `main` через API; GitHub Pages пересобирает сайт
   за 1–3 минуты. Одновременно обновляется `lastmod` в sitemap.xml.
4. Панель сама находит ту же услугу в других разделах (дубли карточек) и предлагает
   применить правку ко всем. Кнопка «Цены» — массовая замена цены по всем разделам
   (ищет по цифрам с учётом написания «4500» / «4 500» / «4&nbsp;500»).
5. Кнопка «+ Услуга» создаёт новую карточку в конце текущего раздела из формы
   (`buildCardHtml` в `js/admin-core.js`): классы обёртки берутся у последней
   карточки раздела, размеры фото подставляются автоматически, кнопки Заказать/
   Подробнее генерируются по образцу сайта — модалки работают без правок скриптов.
   Кнопки «Копия» (клон карточки) и «Удалить» (убирает блок из HTML) — там же.

Правила для ИИ и разработчика:
- **НЕ менять** структуру классов карточек (`card service-card`, `card-img`,
  `service-card-info-pill-label/value`, атрибуты `data-title`, `data-price`,
  `data-description`, `data-full`, `data-images`) — на них завязан парсер панели.
  При изменении разметки карточек — обновить `js/admin-core.js` и прогнать
  `node _tools/test-admin-core.js` (13 тестов, должны быть зелёными).
- **НЕ добавлять** admin.html в sitemap.xml, меню и ссылки с публичных страниц.
- Правки цен владельцем из панели обязывают перегенерировать фид (`gen-feed.ps1`) —
  панель об этом предупреждает.
- Пароль и токен в файлы репозитория не вносить никогда.


**Важно:** в `.kilo/worktrees/evening-equinox/` лежит **старая копия сайта** — не редактируй её и не путай с актуальными файлами в корне.

> ⚠️ **В ФИДЕ ТОЛЬКО РЕАЛЬНЫЕ ДАННЫЕ. Никаких заглушек.**
> Сейчас в `gen-feed.ps1` зашиты настоящие цифры с Яндекс.Карт:
> `$rating = '4.8'`, `$reviews = '17'`, `$exp = '10'` (работаем с 2016 года).
> Значения вида «Рейтинг 5.0 / 50 отзывов» — это выдуманные данные, загруженные
> в выдачу Яндекса; за них поисковик фильтрует домен, и трафик падает с 150/день
> до 1–2/день **независимо от отката кода**. При изменении цифр на Яндекс.Картах
> править эти три переменные и перегенерировать фид. Скрипт сам падает с ошибкой,
> если в фиде снова появятся 5.0/50 или продублируются param.
> Отзывы с Авито (29, рейтинг 5.0) в Yandex-фид намеренно не подмешиваются —
> это другая площадка, проверяемая цифра здесь своя.
>
> ⚠️ **ФИД ЯНДЕКСА НЕЛЬЗЯ ПОДМЕНЯТЬ СТАРЫМИ КОПИЯМИ И РУЧНЫМИ АПЛОАДАМИ.**
> Только запуск `gen-feed.ps1` — он пишет формат «Исполнители»: наборы `<sets>`/`<set-ids>`,
> исполнитель в `<name>`, обязательные `<param>` (Рейтинг, Число отзывов, Годы опыта,
> Регион, Конверсия) и уникальные `<picture>`.
> **Регресс 15.09.2026:** в коммите «восстановлен фид» файл был затёр старым товарным фидом
> из прежних аплоадов — Яндекс.Вебмастер перестал принимать фид, карточки услуг пропали
> из выдачи, переходы из поиска упали почти до нуля.
> Порядок после любых правок цен/услуг: запустить `gen-feed.ps1` → проверить вывод скрипта
> (`Offers: 63, Sets: 6` и «контроль пройден») → закоммитить `yandex_market.xml` и
> `yandex_market.yml` → переотправить фид в Вебмастере.

## 🔧 Технические правила проекта

1. **Кодировка:** UTF-8 без BOM. Все файлы — UTF-8. Не сохраняй с BOM.
2. **Навигация:** шапка с меню копируется на всех страницах; при добавлении нового пункта — обновляй **все** основные HTML-файлы (кроме служебных папок).
3. **Модалки и скрипты:** блоки `contact-modal-overlay`, `orderModal`, `serviceModal`, `successModal`, `mobile-bottom-nav`, копи-кнопка и `toggleSeoText()` обязательны на страницах с карточками услуг — бери за образец файл из корня, а не из черновиков.
4. **Метрика:** Яндекс.Метрика (id 109547647) должна присутствовать в `<head>` каждой публичной страницы.
5. **SEO-поля страницы:** `title`, `meta description`, `canonical`, OG-теги, Twitter-теги, `geo.region`/`geo.placename` — обязательны.
6. **Изображения:** WebP, атрибуты `alt` с ключевыми словами, `loading="lazy"` (кроме hero).
7. **Цены** сверяй с `yandex_market.yml` и пакетами на главной — они там эталонные.
8. **`Host` в robots.txt** — только голый домен, без протокола и пути: `Host: nafnafiki.ru`.
   Значение `Host: https://nafnafiki.ru` невалидно по спецификации Яндекса
   (в директивах `Disallow`/`Sitemap` — наоборот, полный URL с протоколом).
9. **`sitemap.xml`:** каждая публичная страница обязана быть в карте, `lastmod`
   проставлять по фактической дате последнего изменения файла (после правок страницы —
   в том же коммите). В карте не должно быть URL с `noindex` (например `privacy.html`).
10. **SEO-текст (`#seo-container` / `#seo-text`) должен быть открыт роботам.**
    Скрывать текст через `display:none` нельзя: секция обязана иметь класс `open`
    в разметке, а `.reveal` — класс `visible`, иначе ~600 слов уникального текста
    выпадают из индекса, а Яндекс может расценить это как спам.
